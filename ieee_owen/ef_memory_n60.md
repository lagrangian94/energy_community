## 2. 메모리: 문제가 아니라 B&B가 쓴다

모델 자체는 수백 MB인데 프로세스는 최대 private 10.7~14.7 GB(n=60, 24회 평균 12.1 GB, 물리 메모리 평균 7.8 GB)를 쓴다.

| n | 최대 private 평균 (최소~최대) | 최대 물리 메모리 평균 |
|---|---|---|
| 6 | 2.4 GB (2.1~2.5) | 0.7 GB |
| 15 | 5.3 GB (4.3~7.2) | 3.3 GB |
| 30 | 8.3 GB (6.5~11.3) | 5.6 GB |
| 60 | 12.1 GB (10.7~14.7) | 7.8 GB |

파일럿(n=60, 3일차, 2026-10-06)의 시간별 private 메모리: 시작 4.2 GB → 1라운드 root 10.4 GB → B&B 11~14 GB.

추정 내역(로그와 시간축에서 추정, 프로파일링 아님):

| 항목 | 크기 (추정) |
|---|---|
| 파이썬 + numpy/pandas/gurobipy/pyscipopt import | 약 1.7 GB (대부분 확보만 한 버퍼) |
| SCIP 모델 구축 + Gurobi 복사 (SCIP는 복사 후 해제) | 수백 MB |
| root: concurrent LP(primal, dual, barrier 각자 사본) + barrier 분해 | 수 GB의 급증 (파일럿 4 → 10 GB) |
| B&B: 스레드 24개가 각자 presolve 모형의 LP 사본·분해 행렬·작업 배열 | 수 GB |
| 노드 트리 (3 GB 넘는 분은 `NodefileStart`로 디스크) | 최대 3 GB |
| cut pool, 휴리스틱 하위 MIP(RINS 등의 모형 사본) | 수백 MB~수 GB |

즉 시나리오 20개라는 크기보다, **24 스레드 B&B가 모형을 스레드마다 복제하는 구조**가 메모리의 대부분이다. 스레드 수(`Threads`)를 줄이면 비례해 줄지만 탐색 경로와 시간이 바뀐다. `Method`는 고정하지 않는다.

## 3. 이 PC의 여유

16 GB 중 실험 외 사용: Claude 앱 약 1.6 GB, Windows 서비스 1.2 GB, 커널 pool 1.4 GB, Defender 등. WSL VM이 켜지면 1.1~1.3 GB가 더 묶인다. n=60의 최대 사용이 여기에 겹치면 가용 메모리가 0.6~1.0 GB까지 내려가고, 감시 장치(0.7 GB)가 실행을 끊는다(2·16·24일차 n=60, 16일차 n=30).
